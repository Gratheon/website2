Первый комплект датчиков Gratheon для улья должен быть оптимизирован под доступность для DIY-сборки, простую поддержку прошивки и достаточную мощность для HTTPS-телеметрии. Поэтому **ESP32-WROOM DevKit** является выбором по умолчанию для MVP.

## Рекомендация

| Чип / плата | Подключение | Сильные стороны | Слабые стороны | Использование в Gratheon |
| --- | --- | --- | --- | --- |
| **ESP32-WROOM DevKit** | WiFi, BLE | Очень распространённая, дешёвая, поддерживается Arduino, хватает RAM/CPU для TLS + HX711 + датчиков + глубокого сна. | Dev-платы не являются вариантом с минимальным энергопотреблением; качество клонов различается. | **Базовый DIY MVP**. |
| ESP32-C3 | WiFi, BLE | Ниже стоимость и энергопотребление, RISC-V, современная поддержка Espressif. | Меньше выводов и периферии; меньше запаса для будущих аудио/ML-функций. | Вторая поддерживаемая плата после стабилизации MVP-прошивки. |
| ESP32-S3 | WiFi, BLE | Больше RAM/CPU и USB; лучше подходит для будущих экспериментов с аудио/TinyML. | Дороже, чем нужно для весов. | Прототипы с акустикой/edge-ML, не базовые весы. |
| ESP8266 | WiFi | Дешёвый и проверенный вариант для простой телеметрии. | Старее, меньше RAM, слабее путь поддержки TLS. | Только для community-портов, не для первого официального комплекта. |
| STM32 / GD32 + radio | Зависит от модуля | Стабильная embedded-платформа, хороша для кастомной платы с низким энергопотреблением. | Добавляет сложность радио/модуля и нагрузку по поддержке toolchain. | Отложить до кастомной PCB. |
| RP2040 + radio | Зависит от модуля | Отличные инструменты и IO. | У обычного RP2040 нет встроенного WiFi; выше сложность интеграции. | Не рекомендуется для MVP. |
| nRF52 | BLE | Отличный low-power BLE. | Нужен шлюз; не подходит для прямой интернет-телеметрии. | Полезен для будущих sensor nodes, но не для первого WiFi-комплекта. |
| Arduino Mega / ATmega | Нет | Знакомая образовательная плата. | Требует дополнительной сети, слишком громоздкая и энергоёмкая. | Избегать в продукте. |

## Правило выбора подключения

1. **Сначала WiFi** для публичного DIY-комплекта: самый простой onboarding и самая дешёвая поддержка.
2. **ESP-NOW или LoRa-шлюз вторым этапом** для пасек, где несколько ульев находятся рядом, но WiFi есть не у каждого улья.
3. **LTE-M/NB-IoT cellular в последнюю очередь** для платных комплектов для удалённых полей, потому что модемы, антенны, SIM-подготовка и управление питанием повышают сложность и стоимость.

## Последствия для прошивки

- Держать единую кодовую базу прошивки с pin map для каждой платы.
- Стандартный интервал отправки снаружи должен быть 10-15 минут; 1 минута полезна для демо, но расходует батарею.
- Использовать deep sleep между измерениями и по возможности отключать питание HX711/датчиков.
- Хранить WiFi, endpoint, `hiveId`, API token, интервал отправки и calibration factor в энергонезависимой памяти.
- Отправлять JSON в `POST /iot/v1/metrics` с `timestamp` и `dedupeKey`, чтобы повторы были безопасными.
