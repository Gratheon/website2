Мы хотим уведомлять пчеловода в разных сценариях и функциях. Для этого нужен универсальный способ создавать и просматривать уведомления. Уведомления хранятся в БД и отображаются в UI.

## Пользовательская история - настройка каналов уведомлений

- Пользователь открывает страницу настроек
- В разделе `Alerts`
    - выбирает канал уведомлений: `Уведомлять через: [email]`
        - Push на мобильный телефон (если используется мобильное приложение)
        - Email
        - SMS (Twilio?)
        - Telegram-бот
            - [https://telegraf.js.org/#md:introduction](https://telegraf.js.org/#md:introduction)
        - [Интеграция webhooks](../future-ideas/pro-tier-ideas/webhooks-integration.md)
- В типах уведомлений можно выбрать (чекбоксами), какие типы получать (список должен быть длинным)
    - риск роения - [Распознавание маточников на стороне рамки](../hobbyist-tier/queen-cup-detection.md)
    - атаки ос - [Обнаружение атаки ос](../../entrance_observer/todo/🚁%20Hornet%20attack%20detection.md)
    - матка отсутствует - [Распознавание матки](../hobbyist-tier/queen-detection.md)
    - матка не откладывает яйца - [Анализ рамки - обнаружение пятнистого расплода](../future-ideas/pro-tier-ideas/frame-analysis-spotty-brood-pattern-detection.md)
    - слишком высокая доля трутневых ячеек - [Распознавание трутневого расплода](../future-ideas/drone-brood-detection.md)
    - низкая/высокая температура в улье
    - роение уже произошло
    - пользовательская аномалия - привязка к аналитике телеметрии в веб-приложении

## Пользовательская история - получение уведомления об отсутствии матки

- Пользователь загружает фото всех рамок улья
- Все рамки обработаны
- Матка не обнаружена
    - Создаётся уведомление
        
    - Уведомление показывается в шапке
        ![](/about/img/Screenshot%202024-06-20%20at%2014.40.44.png)
        
    - По клику открывается popup уведомления
        
- В зависимости от каналов уведомление доставляется пользователю
    - По email пользователь получает письмо, что `в улье X отсутствует матка`
    - [ ] Нужны хорошие формулировки, ссылки, изображения и дизайн - обратиться к [Designer (UX / UI / Industrial)](https://www.notion.so/Designer-UX-UI-Industrial-454c89d18d7e4eeb822c54d9966bc169?pvs=21)
- После действий по уведомлению пользователь `подтверждает уведомление`, фактически скрывая или удаляя его

## Предлагаемое техническое решение

Создать новый микросервис `alerts`

- добавить отдельную БД
- добавить GraphQL API
    - мутация `createAlert`
    - запрос `alerts`
- сервис выступает прокси. Генерация уведомлений остаётся в сервисах с бизнес-логикой
