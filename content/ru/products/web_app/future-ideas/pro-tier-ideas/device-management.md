---
title: "🎮 Управление устройствами"
---

Чтобы упростить подключение веб-приложения к [Entrance Observer](../../../entrance_observer/entrance_observer.md), [IoT-датчикам улья](../../../../docs/beehive-sensors/beehive-sensors.md), [роботизированному улью](../../../robotic_beehive/robotic_beehive.md) и сторонним источникам телеметрии, нужен отдельный экран управления устройствами.

Сейчас устройства напрямую используют API-токены. Из-за этого позже сложно понять, используется ли токен, каким устройством он используется и когда устройство последний раз взаимодействовало с Gratheon.

Ещё одна проблема - если Gratheon начнёт поставлять собственные устройства, понадобится аналитика, отладка и версионирование по каждому устройству. Для этого нужна отдельная модель данных устройств.

## Предлагаемое решение

В репозитории `web-app`:

- Добавить новый пункт верхнего меню `Устройства`.
- Добавить список устройств:
  - список должен получать данные через GraphQL-запрос.
- Добавить кнопку создания нового устройства и отдельный экран создания, похожий на создание нового улья:
  - тип устройства: [IoT-датчики улья](../../../../docs/beehive-sensors/beehive-sensors.md), [Entrance Observer](../../../entrance_observer/entrance_observer.md), [роботизированный улей](../../../robotic_beehive/robotic_beehive.md) или сторонняя интеграция;
  - номер модели строкой, чтобы понимать, какое ПО работает на устройстве и какой набор функций доступен при серийном производстве;
  - выбор улья с отправкой `hiveId` на backend;
    - опциональный выбор секции с отправкой `boxId` на backend;
  - генерация нового API-токена в `user-cycle` для этого устройства;
    - в `user-cycle` нужно добавить колонку `deviceId` и сохранять её вместе с токеном;
  - `lastUsed` - дата и время последнего использования;
    - поле должно обновляться при API-вызовах, если прошло больше 1 минуты;
  - статус устройства:
    - если `lastUsed` меньше 1 минуты назад, показывать зелёный статус `онлайн`;
    - если `lastUsed` больше 5 минут назад, показывать жёлтый статус `ожидание`;
    - если `lastUsed` больше 1 часа назад, показывать красный статус `офлайн`.
- Добавить экран редактирования устройства:
  - отзыв API-токена для этого устройства;
  - кнопка `Подключиться к устройству` для [Entrance Observer](../../../entrance_observer/entrance_observer.md) и [роботизированного улья](../../../robotic_beehive/robotic_beehive.md):
    - для [Entrance Observer](../../../entrance_observer/entrance_observer.md) кнопка должна запускать [удалённый рабочий стол](../../../entrance_observer/ideas/🎮%20Device%20management%20-%20Remote%20desktop.md) через VNC;
    - для [роботизированного улья](../../../robotic_beehive/robotic_beehive.md) нужны отдельные экраны удалённого управления:
      - [сканирование рамок в реальном времени](../../../robotic_beehive/todo/📸%20Real-time%20frame%20scanning.md);
      - [роботизированная перестановка рамок](../../../robotic_beehive/ideas/🦾%20Robotic%20frame%20reordering.md);
      - [полный осмотр улья](../../../robotic_beehive/todo/📸%20Full%20hive%20inspection.md);
      - [роботизированная изоляция и извлечение рамок](../../../robotic_beehive/ideas/🦾Robotic%20frame%20isolation%20%26%20extraction.md);
      - [роботизированная вставка новых рамок](../../../robotic_beehive/ideas/🦾%20Robotic%20insertion%20of%20new%20frames.md);
      - [управление вентиляцией](../../../robotic_beehive/ideas/🚁%20Ventilation%20control.md);
      - [подвижное дно улья с подсчётом varroa](../../../robotic_beehive/ideas/🦾%20Moveable%20hive%20bottom%20with%20varroa%20counting.md).
  - таблица `Логи устройства`:
    - в идеале здесь должны отображаться данные, которые отправляют клиентские приложения;
    - таблица только для чтения.
- Кнопка удаления устройства должна выполнять soft-delete:
  - перед удалением нужно отозвать API-токен.
- В аккаунте, в списке токенов, показывать, используется ли API-токен устройством. Вместо удаления такого токена нужно вести пользователя на экран устройства.
